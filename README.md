# Service Monitor 3.2.0

Мониторинг доступности HTTP-сервисов в локальной сети с веб-панелью и значком в системном трее.

## Возможности

- Проверка HTTP/HTTPS по расписанию: метод, заголовки, тело, Basic/Bearer-авторизация, ожидаемые коды ответа, проверка текста в ответе, таймаут, редиректы, SSL.
- Панель на русском языке, работает в браузере с любого компьютера в локальной сети. Без учётных записей и ограничений CORS.
- Несколько одновременных пользователей, обновление состояния в реальном времени через SSE.
- Отдельная страница «История»: все запросы плоским списком, фильтры по результату, запуску и периоду, поиск, экспорт в CSV. Удобно держать на втором мониторе.
- Уведомления об ошибках и восстановлении: Telegram, MAX, e-mail (SMTP), произвольный webhook с шаблоном тела.
- Для каждого сервиса можно выбрать, отправлять ли уведомления и в какие каналы.
- Автопроверка, ручной запуск, история проверок, журнал отправок.
- Системный трей: открыть панель, проверить сейчас, включить автопроверку, открыть папку данных, выход.
- Автозапуск вместе с Windows, запуск свёрнутым в трей.
- Резервное копирование и восстановление сервисов и настроек.

## Быстрый запуск

Запустите `setup_and_run.bat`. Скрипт создаст `.venv`, установит зависимости и откроет приложение.

Панель: `http://localhost:8062`. Приложение сворачивается в трей, выход — через меню значка.

Требуется Python 3.10+ для Windows (при установке включите «Add Python to PATH»).

Можно запустить и напрямую:

```powershell
.\.venv\Scripts\python.exe run.py
```

## Сборка exe

```powershell
.\build.bat
```

или

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Результат: `dist\ServiceMonitor.exe` — один самодостаточный файл с иконкой. Python на целевой машине не нужен. Файлы данных создаются рядом с exe в папке `dist\data`.

## Доступ из локальной сети

В настройках панели выберите «Все интерфейсы» и нужный порт (по умолчанию `8062`). Адреса этой машины показаны в разделе «Доступ по сети».

При первом запуске Windows может запросить разрешение брандмауэра — разрешите доступ в частных сетях. Смена адреса и порта применяется после перезапуска.

## Уведомления

1. Откройте раздел «Уведомления» и заполните нужные каналы.
2. Включите канал и общие уведомления, при необходимости включите сообщения о восстановлении.
3. В карточке сервиса выберите «Уведомлять об ошибке» и каналы (или оставьте «все включённые»).
4. Кнопка «Проверить» в канале отправляет тестовое сообщение.

Уведомление об ошибке отправляется при переходе сервиса в состояние ошибки. Повторные сообщения при длительной ошибке задаются в минутах (0 — не повторять). Журнал отправок доступен на той же странице.

## Данные

Все файлы лежат в папке `data` рядом с программой (для сборки — `dist\data`). Если папка недоступна для записи, используется `%LOCALAPPDATA%\ServiceMonitor`:

- `data\services.json` — сервисы;
- `data\settings.json` — настройки и параметры каналов;
- `data\history.json` — история проверок;
- `data\state.json` — текущее состояние сервисов;
- `data\notifications.json` — журнал отправок;
- `data\logs\service-monitor.log` — лог приложения.

Точные пути показаны в разделе «Настройки» на панели. При стандартном расположении старые файлы из корня программы (`services.json`, `results.json`, `BASE.json`, `result.json` и другие) автоматически переносятся в `data`, при этом `results.json` становится `history.json`. Если папка задана явно через `--data-dir` или `SERVICE_MONITOR_DATA`, перенос не выполняется — выбранная папка используется как есть.

Резервная копия из раздела «Настройки» содержит пароли и токены — храните её в защищённом месте.

## Параметры командной строки

```
--no-tray             запуск без значка в трее
--no-browser          не открывать браузер
--start-minimized     не открывать панель при запуске
--data-dir PATH       папка данных
--host HOST           адрес прослушивания
--port PORT           порт
--allow-multi         разрешить несколько экземпляров
--console             лог в консоль
--verbose             подробный лог
--version             версия
```

## API

Основные эндпоинты: `GET /api/state`, `GET|POST /api/services`, `PUT|DELETE /api/services/{id}`, `POST /api/check`, `GET /api/stream` (SSE), `GET|PUT /api/settings`, `GET /api/results`, `GET /api/notifications/log`, `GET /api/health`.

Интерактивная документация: `http://localhost:8062/api/docs`.
